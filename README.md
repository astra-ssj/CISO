# Astra-CISO v3 (decision-loop)

**Astra is where security decisions get made, evidenced, and remembered.**

Not an autonomous CISO. Not an OpenNeko wrapper. Skills compute; humans approve; snapshots are the source of truth.

**Today (this release):** vendor questionnaires from a defensible KB, 5×5 risk, evidence expiry, vendor go/no-go, Postgres snapshots, an honest decision queue, and OpenNeko as a sidecar for watchers/approvals. Cycle time down, evidence up, a decision you can defend.

**Not this release:** live IR, board-ready KPIs, silent mock intel, or an AI Decision Center that invents tickets.

This line ships on branch `release/v3-decision-loop` (`3.0.0-decision.2`). See [RELEASE.md](RELEASE.md), [HONESTY.md](HONESTY.md), [CHANGELOG.md](CHANGELOG.md).

**Key differentiator:** CAIQ Knowledge Transfer with **1,000+ pre-validated Q&A pairs** — replayable, not a new LLM paragraph each time.

## Core Modules

| Module | Description |
|--------|-------------|
| **Command Center** | Queue of real counts + live/empty intel. Does not seed SAMPLE incidents or threats. |
| **Decision Center** | Needs-you queue from evidence expiry and open 5×5 risks. Recorded decisions start empty. |
| **Strategy & OKRs** | OKRs and projects from Prisma. Defense Matrix unscored until assessments exist. KPI tab still mixed — see HONESTY.md. |
| **Governance & Risk** | Risk register (5×5 skill), policies, evidence, audit. Compliance heatmap still seeded. |
| **Vendor Risk** | CAIQ match/score skills, knowledge base, vendor registry, optional Shodan. |
| **Incidents** | Playbooks from Prisma. Register empty until used. War Room binds `Incident` or is labeled exercise mode. |
| **Threat Intelligence** | Live feeds or empty. World Monitor static layers + live cyber points. No silent MOCK IOCs. |

## Core Operational Workflows

To get the most out of Astra-CISO, modules are designed to interconnect. Here are the three primary workflows:

### 1. The Vendor Onboarding Flow
- **AppSec & Intelligence:** Enter a vendor's domain to natively run a Shodan infrastructure scan and evaluate exposed services. 
- **Vendor Risk:** Send the vendor a CAIQ assessment, then run their raw answers through the Knowledge Transfer Engine to automatically score them against 1,000+ pre-validated Knowledge Base entries.
- **Decision Center:** Automatically receive an AI-prioritized "Go / No-Go" decision on finalizing the vendor relationship based on the risk threshold.

### 2. The Threat Response Flow
- **Intelligence Dashboard:** A new critical IOC triggers an alert generated by Abuse.ch.
- **Attack Surface:** Cross-reference the IOC against your known mapped assets to determine blast radius.
- **Incidents:** Open an Active Incident, spin up the War Room, and pull in the AI Copilot to correlate the threat intel data against your active compliance policies and draft a mitigation response.

### 3. The Executive Posture Flow
- **Governance & Risk:** Map the quantitative FAIR risk scenarios to your deployed organizational policies.
- **Strategy & OKRs:** Connect the risk register to your high-level OKRs and track program progress.
- **Command Center:** Output a synthesized AI Executive Briefing to hand straight to the board showing the alignment between the security spending, policy enforcement, and actual threat reduction.

## Quick Start

### With Docker

```bash
git clone https://github.com/SristiNative/CISO.git
cd CISO
cp .env.example .env.local
# Edit .env.local — AUTH_SECRET + DATABASE_URL (Postgres)
docker compose up -d postgres
npx prisma generate && npx prisma db push && npx prisma db seed
npm run dev
# Open http://localhost:3000
```

### Without Docker

```bash
docker compose up -d postgres
npm install
cp .env.example .env.local
# Edit .env.local — DATABASE_URL=postgresql://astra:astra@localhost:5432/astra
npx prisma db push
npx prisma db seed
npm run dev
# Open http://localhost:3000
```

> [!WARNING]
> By default, the database seed (`npx prisma db push` via `prisma/seed.ts`) will create a demo user with the credentials **`ciso@astra.ai` / `admin123`**. Ensure you change this or drop the mock users before deploying to production. Never commit `.env.local` or `.db` files.

### Testing & QA (Local)

All integration and unit paths have been strictly typed and patched for Next.js 16 Edge runtime compatibility.

```bash
# Run strict TypeScript environment validation
npx tsc --noEmit

# Run unit and integration Vitest suites
npm run test

# Run vulnerability package audit
npm audit
```

## CAIQ Knowledge Transfer

The flagship feature for vendor risk automation:

- **1,000+ pre-validated** security Q&A entries
- **Multi-company, multi-product** configuration
- **4-tier confidence matching:** Direct → Semantic → AI Adapted → Manual
- **JSON import/export** for knowledge portability
- **Learning loop** — gets smarter with each assessment
- Reduces vendor risk assessments from **days to hours**
